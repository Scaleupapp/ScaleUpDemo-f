# Phase B — Capstones Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan workstream-by-workstream. Tasks use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship long-form Capstone sessions to production behind the same Plan/Mastery/Readiness loops Phase A wired up. Mobile is command surface, laptop is work surface.

**Architecture:** Net-new web app (Next.js 15) connects to a per-session managed sandbox (e2b.dev) via WebSocket. Mobile pairs via 6-digit code, monitors via heartbeat, receives async evaluation. Backend extends `scaleup-backend` with `sandboxOrchestrator`, `pairingService`, `capstoneEvaluator` (BullMQ), and `contentGenerator` capstone-aware variant.

**Tech Stack:**
- Backend: Node 20 + Express + Mongoose + BullMQ + Redis + WebSocket (`ws`) + e2b SDK + S3
- Web: Next.js 15 (App Router) + Monaco Editor (@monaco-editor/react) + Socket.io-client + TanStack Query
- Mobile: existing iOS (SwiftUI) + Android (RN) coding feature folders extended
- LLM: existing `llmRouter` (Claude Opus 4.7 generator, Sonnet 4.6 evaluator, Gemini 2.5 Pro validator)
- Sandbox: **e2b.dev** managed (per spec §9.5 — managed first, self-host post-launch)

### Pairing service

- [ ] **WS2.1 — Generate 6-digit code, store, expire**

```js
// src/coding/services/pairingService.js
const crypto = require('crypto')
const PairingCode = require('../../models/PairingCode')
const TEN_MIN_MS = 10 * 60 * 1000

async function mintCode({ userId, sessionId }) {
  // 6-digit numeric, padded. Collision-retry up to 5x.
  for (let i = 0; i < 5; i++) {
    const code = String(crypto.randomInt(0, 1_000_000)).padStart(6, '0')
    try {
      const doc = await PairingCode.create({
        code, user_id: userId, session_id: sessionId,
        expires_at: new Date(Date.now() + TEN_MIN_MS)
      })
      return { code, expiresAt: doc.expires_at }
    } catch (e) {
      if (e.code !== 11000) throw e  // not a dup-key — surface
    }
  }
  throw new Error('Pairing code collision after 5 retries')
}

async function redeem(code) {
  const doc = await PairingCode.findOneAndUpdate(
    { code, used_at: null, expires_at: { $gt: new Date() } },
    { used_at: new Date() }, { new: true }
  )
  return doc  // null if invalid/used/expired
}

module.exports = { mintCode, redeem }
```

- [ ] **WS2.2 — Sandbox orchestrator (e2b adapter)**

Per WS1.4 interface. Provision returns `{ sandboxId, hostUrl }`. Per spec §9.5, e2b is MVP provider.

```js
// src/coding/services/sandboxAdapters/e2bAdapter.js
const { Sandbox } = require('@e2b/code-interpreter')

async function provision({ image, files, env, limits }) {
  const sbx = await Sandbox.create({
    template: image,           // e.g. 'node-20', 'python-3.12'
    envs: env,
    timeoutMs: limits.wallClockMs
  })
  // Copy starter repo files in
  for (const f of files) {
    await sbx.files.write(f.path, f.content)
  }
  return { sandboxId: sbx.sandboxId, hostUrl: sbx.getHost(3000) }
}

async function destroy(sandboxId) {
  const sbx = await Sandbox.connect(sandboxId)
  await sbx.kill()
}

async function runCommand(sandboxId, cmd) {
  const sbx = await Sandbox.connect(sandboxId)
  const t0 = Date.now()
  const r = await sbx.commands.run(cmd)
  return { stdout: r.stdout, stderr: r.stderr, exitCode: r.exitCode, durationMs: Date.now() - t0 }
}

// ... watchFileEvents, getStats per interface
module.exports = { provision, destroy, runCommand, uploadFiles, watchFileEvents, getStats }
```

### WebSocket server

- [ ] **WS2.5 — Session room WS server**

Per spec §7.3, 4 message types: `session.pair`, `session.stats`, `session.control`, `session.lifecycle`.

```js
// src/coding/websocket/wsServer.js
const { WebSocketServer } = require('ws')
const url = require('url')

function attach(httpServer, { redis }) {
  const wss = new WebSocketServer({ server: httpServer, path: '/ws/coding' })
  const rooms = new Map()  // sessionId → Set<ws>

  wss.on('connection', (ws, req) => {
    const { query } = url.parse(req.url, true)
    const { sessionId, token, role } = query  // role: 'mobile' | 'laptop'
    // ... verify JWT, join room
    rooms.get(sessionId)?.add(ws) ?? rooms.set(sessionId, new Set([ws]))
    ws.on('message', (raw) => handleMessage(JSON.parse(raw), { sessionId, role, rooms, redis }))
    ws.on('close', () => rooms.get(sessionId)?.delete(ws))
  })

  return { broadcast: (sessionId, msg) => rooms.get(sessionId)?.forEach(w => w.send(JSON.stringify(msg))) }
}
```

- [ ] **WS4.6 — Anchor-drift detection (spec §8.3)**

Each bundle has 3–5 `rubric_anchors`. After eval, check if Sonnet's score on those anchors differs > 2 points from the deterministic check. If yes, flag for human review + re-run with stricter prompt.

```js
// src/models/EvaluationAnchor.js — cached anchor results per bundle
// src/coding/services/capstoneEvaluator.js
async function checkDrift(bundleId, evaluatorScores) {
  const anchors = await EvaluationAnchor.find({ bundle_id: bundleId })
  const drift = anchors.map(a => Math.abs(a.expected_score - evaluatorScores[a.dimension]))
  return drift.some(d => d > 2)
}
```

## Execution

This plan is intentionally workstream-granular rather than line-granular because Phase B is a 3-month effort, not a 3-day one. Each WS has tasks that are concrete enough to start work on; each task names files and shows code patterns for the non-obvious parts.

Two ways to execute from here:

1. **Subagent-driven** (recommended): use `superpowers:subagent-driven-development` workstream-by-workstream. Controller dispatches one workstream at a time; each task within a workstream is one subagent invocation with the full task text + relevant spec excerpts.

2. **Inline / parallel sessions**: use `superpowers:executing-plans`. Open parallel sessions per workstream, controller (you) checks in at workstream gates.

The first decision to make in either mode: **WS0 sandbox spike**. Until e2b is validated, nothing else should run. If WS0 returns no-go, the plan branches (Daytona adapter, possibly StackBlitz WebContainers for browser-only sandboxing — material rework).
