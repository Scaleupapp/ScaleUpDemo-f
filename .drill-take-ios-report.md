## Drill Take Approach
**Thin placement-specific wrapper (`PlacementDrillTakeView`), NOT `DrillModalView` reuse.**

`DrillModalView` was not reusable cleanly because it owns a `DrillSession` which fetches from `/drills/today` and starts a new attempt. The placement context has an already-created DrillAttempt (`engine.sessionId`). Instead:
- `PlacementDrillTakeView` manages its own `PlacementDrillPhase` state enum (brief / input / submitting / result / error)
- Reuses `PromptDrillInputView`, `VerifyDrillInputView`, `DecomposeDrillInputView` unchanged (all three are purely presentational)
- Reuses `DrillSubmittingView` unchanged (no params)
- Reuses `DrillResultView` unchanged (purely presentational, takes graded result + onDone closure)
- Submit/poll uses new `PlacementsAssessmentsApi.submitPlacementDrill` + `pollPlacementDrillResult` with `engine.sessionId` as the attemptId

## Deferred / Known Limitations

- **Starter repo** field is modelled (`starterRepo: StarterRepo?` in AssessmentMeta) but the UI does not render it — refactor drills with starter repos show an "unsupported" placeholder (matching D2C behavior)
- **Grade poll background task** for drill sessions (submitted→graded transition while the take sheet is closed) is not wired up — the list reload on dismiss + foreground refresh handles it for now
