## Backend Shape Findings (confirmed against studentAssessments.js + models)

### GET /api/v2/me/assessments
- Returns `{ success, data: [{ assessment, session }] }` as documented.
- `assessment._id` is a Mongoose ObjectId (serialises to String in `.lean()`) — mapped via `CodingKeys` `_id → id`.
- `opensAt`/`closesAt` are `Date` fields; with `.lean()` they serialise as ISO8601 strings. Modelled as `String?` to avoid date-decoding strategy conflicts (V2APIClient uses the default Apple `timeIntervalSinceReferenceDate` decoder, not ISO8601).
- `session` can be `null` — modelled as `PlacementSessionLite?`.

### POST /api/v2/me/assessments/:id/start
- Returns `{ success, data: { assessmentSessionId, engine: { type, sessionId?, quizId? }, meta: { systemInstruction? } } }`.
- `engine.sessionId` and `engine.quizId` are ObjectIds — both `String?` so decoding is tolerant.
- `meta` is best-effort (backend catches `getStartMeta` errors) — modelled as `AssessmentMeta?`.

### POST /api/v2/me/assessments/sessions/:sessionId/sync
- Returns `{ success, data: { status, result } }` where `result` can be `null` — modelled as `PlacementSessionResult?`.

### EmptyBody
- `V2APIClient` has a private `EmptyBody` struct; `DiagnosticService` also defines a local one. A private `_EmptyBody: Codable` is defined inside `PlacementsAssessmentsApi` to avoid any redeclaration conflict.

## Concerns / Known Limitations
1. **Date display**: `opensAt`/`closesAt` are decoded as raw strings; the row card does not currently display them. Adding a "Opens at…" line is straightforward but was out of scope.
2. **Single-attempt enforcement**: the backend enforces one attempt at DB level (`unique` index on `assessmentId + userId`). The iOS card disables tap if `session.status` is `graded` or `submitted`. The `in_progress` status still allows re-tap — on second call the backend will return the existing session's engine IDs, which is safe.
3. **`saveAndEvaluate` is private**: `attachSession` calls it indirectly via the timer closure (internal to the same class). This compiles and runs fine; no access-level change was needed.
4. **Interview result sync timing**: `PlacementInterviewTakeView` calls `onComplete()` when `vm.state == .results`. The `sync` POST fires after that, which is correct (the interview is fully evaluated before we notify the assessment backend).
